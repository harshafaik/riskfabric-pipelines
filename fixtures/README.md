# Fixtures

`fixtures/inbox/` holds 31 committed partitions — one customer snapshot and 30
daily transaction files — produced by `scrip`. They are committed so that a clean
clone and CI can run the pipeline without building or running the generator.

Provenance:

```bash
scrip fixtures --out-dir /tmp/refs
scrip generate --customers 500 --seed 42 --days 30 \
  --base-date 2026-01-31T00:00:00Z --txns-per-customer 3..20 \
  --input-dir /tmp/refs --out-dir /tmp/out
python fixtures/build_fixtures.py --source /tmp/out --out fixtures/inbox
```

- Seed `42`, 500 customers, window `2026-01-01` to `2026-01-30`.
- Same seed and arguments produce the same bytes; `scrip` reads no wall clock.
- 8,596 transaction rows across 30 daily files, plus a 500-row customer snapshot
  taken as of `2026-01-01`.
- Generated by scrip schema **v2** (`timestamp` is `Datetime(us, UTC)`,
  `registration_date` is `Date`). `build_fixtures.py` reads
  `scrip.schema_version` from the source Parquet and exits non-zero if it is not
  `2`, so a future v3 fails here instead of producing a silently wrong fixture.

`build_fixtures.py` splits the generator's single `transactions.parquet` into
daily partitions and places the customer snapshot on the first day. It is kept in
the repository so the fixture can be regenerated at a different scale, but it is
not needed to run the pipeline or the tests.
